## 1. Executive Summary

The solution uses multi-channel blocking followed by an ensemble of LightGBM and XGBoost models. Names and addresses are normalized, candidate pairs are generated independently by country, and candidates are ranked with pairwise and group-context features. Country-level bipartite deduplication and precision-oriented thresholds are applied before producing the final files.

## 2. Methodology

### 2.1 Problem analysis

The input contains noisy business names and addresses with inconsistent case, punctuation, diacritics, abbreviations, legal suffixes, scripts, transliteration, missing fields, and OCR-like digit errors. A match may therefore be identified by agreement across several weak signals rather than by one exact field.

### 2.2 Solution strategy

**Approach type:** Hybrid blocking, gradient-boosted pairwise classification, and global post-processing.

**Production entry point:** `code/business_entity_resolution/src/run_pipeline.py`

The pipeline processes France, the US, and India separately, then merges country results in the original Source 1 order.

## 3. Candidate generation (blocking)

Blocking keys are generated by `blocking.py` after normalization by `preprocessor.py`. The blocking channels include:

- Normalized business-name keys
- Name variants and phonetic skeletons
- Prefix and token keys
- Address-field and address-token keys
- Postal-code and numeric-address keys
- Country partitioning

Common tokens are down-weighted using document frequency. Candidates are combined using name/address synergy and capped at the configured top-K pool. This keeps the comparison space manageable while retaining candidates found by different complementary signals.

The complete candidate set is written to `output/candidate_pairs.tsv` before final score thresholding, so it can be audited independently of the final matches.

## 4. Matching model

The feature pipeline combines 50 base pairwise features with 18 group-context features, for a total of 68 Stage-2 features.

### Name features

- Normalized exact agreement
- Token and character similarity
- Name variants
- Phonetic skeleton agreement
- Token overlap and weighted blocking scores

### Address features

- Address-token overlap
- Street and house-number agreement
- Numeric-token agreement
- Postal-code agreement
- Character-level address similarity
- Shifted or reordered address components

### Model ensemble

The production scorer loads these artefacts from `output/models/`:

- `lgbm_exp007_pure_fold0.txt`
- `lgbm_exp007_ext_fold1.txt`
- `xgb_exp007_pure_fold2.json`
- `xgb_exp007_ext_fold3.json`
- `stage2_lgb_exp007_fold0.txt`
- `stage2_xgb_exp007_fold2.json`

The ensemble produces candidate probabilities. Country-specific thresholds, drop-off ratios, rescue rules, and bipartite deduplication are then applied.
